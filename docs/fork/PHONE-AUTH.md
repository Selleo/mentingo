# Вход по номеру телефона (SMS-код)

Функция позволяет пользователям LMS входить по номеру телефона и одноразовому коду из SMS
вместо пароля. Ориентирована на школу с пользователями из России и Монголии (lms.wiki).

## Что сделано

**API (`apps/api/src/phone-auth`)**

| Метод и путь                        | Доступ                | Назначение                                                                      |
| ----------------------------------- | --------------------- | ------------------------------------------------------------------------------- |
| `GET /api/auth/phone/config`        | публичный             | `{ enabled }` — включена ли функция (веб по нему показывает/прячет UI)          |
| `POST /api/auth/phone/request-code` | публичный             | `{ phone }` → отправить код входа (ответ всегда одинаковый)                     |
| `POST /api/auth/phone/verify`       | публичный             | `{ phone, code, rememberMe? }` → вход, те же cookies, что и при email           |
| `POST /api/user/phone/request-code` | авторизованный        | `{ phone }` → код на новый номер для привязки к своему аккаунту                 |
| `POST /api/user/phone/verify`       | авторизованный        | `{ phone, code }` → сохранить номер как подтверждённый                          |
| `DELETE /api/user/phone`            | авторизованный        | отвязать номер от своего аккаунта                                               |
| `PATCH /api/user/admin?id=…`        | админ (`user.manage`) | поле `phone`: задать/очистить номер пользователя (сохраняется неподтверждённым) |

- В таблицу `users` добавлены `phone` (E.164, например `+79161234567`) и `phone_verified_at`;
  уникальный индекс `(tenant_id, phone)` — один номер на одного пользователя в пределах школы.
  Миграция `0201_add_phone_to_users` только добавляет nullable-колонки и индекс, существующие
  данные не меняются. API применяет миграции автоматически при старте.
- Номера нормализуются через `libphonenumber-js`. Принимаются Россия и Казахстан (+7) и Монголия
  (+976). Номера без `+` трактуются как российские (`8 916 123-45-67`, `9161234567`), а 8-значные
  — как монгольские (`99112233`).
- Вход по телефону возможен только для уже существующих пользователей этой школы, у которых указан
  этот номер. Регистрации «только по телефону» нет (школа работает по приглашениям).
- После ввода правильного кода: если `phone_verified_at` пустой — он заполняется, затем выдаётся та же
  сессия, что при входе по email. Если у пользователя включена или обязательна (по роли) MFA —
  пользователь попадает на тот же шаг MFA, что и после пароля. Архивные и удалённые пользователи
  войти не могут. При включённом «обязательном SSO» вход по телефону запрещён, как и вход по email.
- Самостоятельно пользователь меняет номер только через подтверждение SMS-кодом (`PATCH /api/user`
  с полем `phone` для обычного пользователя возвращает 403).

**Веб (`apps/web`)**

- Страница входа: вкладки «По email / По телефону». Шаги: номер → «Получить код» → 6 цифр кода с
  таймером повторной отправки (60 с) → «Войти». Ссылка «Изменить номер».
- Настройки → Аккаунт: карточка «Номер телефона» — текущий номер и статус (подтверждён / нет),
  ввод нового номера → код из SMS → «Подтвердить», кнопка «Удалить номер».
- Админка → Пользователи → карточка пользователя: поле «Телефон» и подпись о статусе подтверждения.
- Весь телефонный UI скрыт, если `GET /api/auth/phone/config` вернул `enabled: false`.
  Отдельного `VITE_`-флага нет — включение управляется только переменными API.
- Тексты добавлены во все 8 локалей (русский и английский полностью, остальные — английский текст).

## Переменные окружения (API, `.env.prd.api`)

| Переменная           | Обязательна  | Описание                                                                                            |
| -------------------- | ------------ | --------------------------------------------------------------------------------------------------- |
| `PHONE_AUTH_ENABLED` | да           | `true` — включить функцию. Любое другое значение/пусто — выключено                                  |
| `SMSRU_API_ID`       | в продакшене | Ключ API из личного кабинета SMS.RU. В `NODE_ENV=production` без него функция считается выключенной |
| `SMS_SENDER`         | нет          | Имя отправителя, одобренное в SMS.RU. Пусто — отправитель SMS.RU по умолчанию                       |
| `PHONE_OTP_SECRET`   | нет          | Секрет для HMAC кодов (`openssl rand -base64 32`). По умолчанию используется `JWT_SECRET`           |

Для локальной разработки достаточно `PHONE_AUTH_ENABLED=true`: без `SMSRU_API_ID` и вне
продакшена коды печатаются в консоль API (`[DEV SMS] to +7******4567: Код входа в LMS: …`).
В продакшене этот режим невозможен.

## Настройка SMS.RU

1. Зарегистрируйтесь на <https://sms.ru>, подтвердите аккаунт.
2. Скопируйте ключ `api_id` из личного кабинета (раздел для программистов / API) → `SMSRU_API_ID`.
3. Пополните баланс. При нулевом балансе SMS.RU отвечает кодом 103 («Недостаточно средств») —
   в логах API будет `SMS.RU error 103: Insufficient funds`. Проверьте тарифы на Монголию: отправка
   за рубеж стоит заметно дороже.
4. Имя отправителя (буквенное, например `LMSWiki`) нужно зарегистрировать в кабинете SMS.RU и
   дождаться одобрения (для операторов РФ требуется регистрация отправителя; может занять несколько
   дней и потребовать документы). До одобрения оставьте `SMS_SENDER` пустым — иначе ошибка 105.
5. Рекомендуется в кабинете SMS.RU ограничить отправку по IP-адресу VPS и включить уведомления о
   низком балансе.
6. Текст сообщения: «Код входа в LMS: 123456. Никому не сообщайте его.» (для пользователей с
   английским языком интерфейса — английский вариант). Для привязки номера в настройках:
   «Код подтверждения телефона в LMS: …».

Коды ошибок SMS.RU, которые попадают в лог: 102 неверный api_id, 103 недостаточно средств,
104 неверный номер, 105 неверный отправитель, 107 номер запрещён, 110 дубль сообщения,
112 дневной лимит на номер, 113 заблокировано модератором, 150 системная ошибка SMS.RU.

## Как привязать телефоны существующим пользователям

- **Администратор:** Админка → Пользователи → пользователь → поле «Телефон» → «Сохранить». Номер можно
  вводить в любом привычном формате, он сохранится как `+7…`/`+976…`. Такой номер считается
  неподтверждённым до первого успешного входа по SMS.
- **Пользователь:** Настройки → Аккаунт → «Номер телефона» → ввести номер → «Получить код» → ввести
  код → «Подтвердить».
- **Массово (SQL):** при необходимости можно заполнить `users.phone` напрямую, строго в формате E.164
  (`+79161234567`), без пробелов. Номера в другом формате не будут найдены при входе. Дубликаты
  внутри одной школы запрещены уникальным индексом.

## Безопасность

- Код: 6 цифр, `crypto.randomInt`. В Redis хранится только HMAC-SHA256 кода, привязанный к школе,
  назначению (вход / привязка), пользователю (для привязки) и номеру. Сам код нигде не хранится.
- Срок жизни кода 5 минут, не более 5 попыток ввода, сравнение за постоянное время, код удаляется
  после успешного ввода (повторно использовать нельзя), при превышении попыток — сгорает.
- Лимиты: повторная отправка на номер не чаще раза в 60 с, не более 5 кодов в час на номер,
  плюс ограничение 10 запросов в минуту на IP для эндпоинтов входа и привязки (штатный throttler API).
- Защита от перебора пользователей: на `request-code` ответ одинаковый для существующих и
  несуществующих номеров, лимиты применяются одинаково, а SMS отправляется в фоне, чтобы время ответа
  не выдавало наличие аккаунта. SMS уходят только на номера, реально привязанные к пользователям, —
  расходы на SMS ограничены числом таких номеров × 5 в час.
- В логах номер маскируется (`+7******4567`), коды не логируются (кроме dev-провайдера вне продакшена).
- Параметры SMS.RU (включая `api_id` и текст) передаются в теле POST-запроса, а не в URL.
- Номер телефона не отдаётся в публичных ответах API: только самому пользователю (`current-user`,
  ответ входа) и администраторам (карточка и список пользователей, журнал действий при изменении).
- Замечание: лимит по IP опирается на `X-Forwarded-For`. Убедитесь, что обратный прокси на VPS
  перезаписывает этот заголовок, а не дописывает к значению клиента.

## Чек-лист ручной проверки в продакшене

1. В `.env.prd.api` заданы `PHONE_AUTH_ENABLED=true`, `SMSRU_API_ID`, при необходимости `SMS_SENDER`;
   контейнер `api` перезапущен.
2. `curl https://lms.wiki/api/auth/phone/config` → `{"data":{"enabled":true}}`.
3. В логах API при старте нет ошибок миграций; в БД есть колонки `users.phone`, `users.phone_verified_at`.
4. Страница входа показывает вкладки «По email / По телефону»; вход по email работает как раньше.
5. Администратор задаёт тестовому ученику свой номер (в формате `8 9xx xxx-xx-xx`), в карточке
   сохраняется `+79xx…` и подпись «Не подтверждён».
6. Вход по телефону: вкладка «По телефону» → номер → «Получить код» → SMS приходит в течение минуты,
   текст «Код входа в LMS: … Никому не сообщайте его.» → ввод кода → попадание в личный кабинет.
7. В карточке пользователя статус стал «Подтверждён».
8. Неверный код → «Неверный код или срок его действия истёк»; 5 неверных попыток → код сгорает.
9. Повторный запрос кода раньше 60 с невозможен (кнопка с таймером; API отвечает 429).
10. Незарегистрированный номер → то же сообщение «Если номер зарегистрирован, мы отправили код», SMS
    не приходит.
11. Архивный пользователь не может войти по телефону.
12. Пользователь с MFA после ввода SMS-кода попадает на шаг MFA.
13. Настройки → Аккаунт → «Номер телефона»: привязка нового номера с подтверждением, удаление номера.
    Попытка привязать номер другого пользователя → «Этот номер уже используется другим пользователем».
14. Монгольский номер (`+976…`) — SMS доходит (проверить тариф/баланс SMS.RU).
15. В логах API нет полных номеров и кодов.
16. Выключение: `PHONE_AUTH_ENABLED=false` → перезапуск → вкладка «По телефону» и карточка в
    настройках пропали, `request-code` отвечает 403.
