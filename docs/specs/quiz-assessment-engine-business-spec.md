# Quiz Assessment Engine Business Spec

## Business Overview

The Quiz Assessment Engine lets course authors add scored checks inside Mentingo courses. It gives learners a structured way to answer questions, submit an assessment, see their score, and retake the quiz when the course rules allow it.

For HR and L&D teams, quizzes make learning completion more meaningful. Instead of tracking only whether a learner opened a lesson, teams can require a passing score, control retake attempts, and use quiz completion as part of course progression and certificate workflows.

The core workflow starts in curriculum authoring, where a creator adds a quiz lesson and configures questions plus quiz settings. Learners later answer the quiz in the lesson player, submit their answers, and progress only when the quiz rules are satisfied.

## Who Uses It

- Course authors create quiz lessons and add question types that match the learning objective.
- L&D administrators configure passing thresholds, attempt limits, cooldowns, and optional time limits for assessment governance.
- Learners submit answers, review scores, and retake quizzes when allowed.
- Reviewers grade open answers (brief and detailed responses) that wait for manual review.
- Training managers use quiz outcomes as evidence that learners understood required material.

## Feature Functions

- Create quiz lessons inside the curriculum builder.
- Add single choice, multiple choice, true/false, photo choice, fill-in-the-blanks, matching, brief response, and detailed response questions.
- Build matching questions from at least two translatable pairs with unique matches, reorder them, and choose whether the question needs every pair right or earns a share of its point for each correct pair.
- Reorder questions and edit quiz translations while locking structural edits in non-base languages and showing base-language text as an authoring reference.
- Configure passing threshold, optional attempt limit, optional retake cooldown, and an optional time limit (1–300 minutes by default, set by `ASSESSMENT_TIME_LIMIT_MINUTES.MAX` in `@repo/shared`).
- Require learners to answer every quiz question before submission, except on timed quizzes where unanswered questions score 0 points.
- Run timed quizzes against a server-side clock: the learner sees the time limit and explicitly starts the attempt, a countdown stays visible while answering and warns during the last minute, answers are autosaved, a page reload resumes the same attempt with its saved answers, and the attempt is submitted automatically when time runs out.
- Score learner submissions and store question results.
- Let authors mark brief and detailed responses as "Graded by reviewer"; without it they keep counting as correct.
- Hold quizzes with reviewer-graded open answers in a "Waiting for review" state until a reviewer grades them.
- Give reviewers a "Quiz grading" queue with filters and a grading view where they mark each answer as pass or fail and leave a comment; grading the last open answer finalizes the score and completes the lesson when passed.
- Show learners their final score, the points for each reviewer-graded question, and the reviewer's comment.
- Tell learners in the app and by email when their quiz has been graded, and send reviewers one daily email digest about new answers waiting in the queue.
- Write personal result messages per quiz for score ranges (by default 0–49%, 50–79%, 80–100%), with the learner's first name and score filled in, and choose whether learners see the score with messages and answer corrections, the score with messages only, or no feedback.
- Show feedback after submission, including correct-answer context for failed gap-filling questions when feedback is enabled.
- Hide answer-level feedback after submission, retakes, and privileged lesson views when course quiz feedback is disabled.
- Mark the lesson complete only when the learner passes the quiz.
- Let learners retake eligible quizzes and show why retake is unavailable when attempts or cooldown rules block it.

## End-User Value

Quizzes help organizations confirm knowledge, not just content exposure. HR and L&D teams can add lightweight assessments to compliance, onboarding, or skills training, while learners get clear feedback about their score and whether another attempt is available.

## How It Works

A course author adds a quiz lesson in the curriculum builder, gives it a title, chooses question types, fills in answer options or response fields, and configures assessment rules. If the course is translated, Mentingo allows translation edits while preventing non-base-language structural changes such as adding or reordering questions. Empty translated quiz fields show their base-language text as a placeholder; structured gap-fill sentences show a separate read-only base-language preview so authors can translate them without changing the underlying blank structure.

A learner opens the quiz lesson, answers every rendered question, and submits the form. Mentingo validates that no expected question is missing, evaluates the answers, calculates the percentage score, and compares the result with the passing threshold. Passing submissions complete the lesson and can unlock course progression; failed submissions keep progression rules in place.

After submission, learners can review which answers were accepted when quiz feedback is enabled for the course. Answer content follows the selected course content language, falling back to the course base language when unavailable. The UI supplies localized feedback headings; the API returns answer content without a “Correct answer” prefix. Matching questions colour each placed match as right or wrong and show the correct match under wrong or unanswered pairs. Fill-in-the-blanks questions show the correct completed sentence for failed answers, so learners can understand the intended wording instead of seeing only the words they chose. When course feedback is disabled, Mentingo still records the score and submitted answer but keeps answer-level correction details hidden, including after a learner starts and submits a retake or when an admin opens the lesson view.

Authors can also tell each learner what their result means. In the quiz settings, the author splits 0–100% into score ranges and writes a rich-text message for each one; a new quiz starts with three ranges (0–49%, 50–79%, 80–100%). The ranges must cover 0–100% with whole-number, inclusive bounds and no gaps or overlaps; a range may have no message, and an author can remove all ranges to skip messages. Messages can use `{{firstName}}` and `{{score}}`, which Mentingo fills in with the learner's first name and score. Messages are translated with the rest of the quiz, and the learner sees the message for their content language. Translators can edit the messages in another language, but the ranges themselves (their bounds, adding or removing a range, and the feedback mode) can only be changed in the quiz's base language; when the author adds, removes, or moves ranges there, the existing translations stay with their range. The author also picks how much feedback learners get: "Score and messages" shows the score, the range message, and per-question corrections and explanations; "Score only" shows the score and the range message but hides which answers were right; "No feedback" shows no message and no corrections. These modes apply only while quiz feedback is enabled for the course: when the course setting is off (or in a public course preview), learners see no message and no corrections, whatever the quiz mode. Mentingo picks the range that contains the score rounded down, which is the score the learner sees. When the quiz contains reviewer-graded open answers, the message is held back until the reviewer finishes grading; while the attempt waits for review, "Score only" still shows the partial count of graded questions answered correctly, without per-question marks. Feedback ranges and the feedback mode are copied when a course is duplicated or shared with another organization (and updated on later syncs), and exported and imported in course archives. SCORM exports respect the feedback mode for per-question corrections (shown only in "Score and messages" while course quiz feedback is on) but do not include the range messages.

Brief and detailed responses count as correct whenever an answer is submitted, unless the author switches on "Graded by reviewer" for that question in the quiz editor. Existing open questions were kept on the always-correct behaviour, so reviewer grading only applies where an author opts in. When a submission contains reviewer-graded open answers, Mentingo grades the automatic questions right away but saves each open answer as pending with 0 points and keeps the whole attempt pending, without a score, result, or graded date. The lesson is not completed, no quiz-completed or lesson-completed event is emitted, and the learner sees "Waiting for review" on the quiz, in the course outline, and in the lesson sidebar. While waiting, the learner sees their own submitted answers and a partial result: automatically graded questions show their right or wrong marks and a count of correct graded questions, while reviewer-graded answers show "Waiting for review" and no score is shown. When quiz feedback is disabled for the course, the partial result is hidden as well. The learner cannot resubmit or retake the quiz. The pending attempt still counts toward the attempt limit and cooldown. Learner statistics and course quiz results leave pending attempts out, and certificates cannot be issued because the lesson stays incomplete. If the learner repeats the course, the pending attempt stays with the earlier run. Admins in learning or support mode and freemium learners follow the same rule. Attempts already graded are not re-graded when an author changes a question's review setting. Quizzes without reviewer-graded open questions are graded immediately as before.

Reviewers (and admins) open the "To grade" queue from the sidebar, which lists the organization's reviewer-graded answers, oldest first, with filters by course, lesson, learner, and status (pending by default, graded answers can be shown for re-grading) shown as removable filter pills with a reset action, and pagination, in the same table layout as other list pages. Reviewers never see or grade their own answers; admins do, so they can grade quizzes they took themselves (for example while trying out a course). A reviewer lands on the queue after signing in. The grading view shows the question, the learner's answer, the author's reviewer instructions when present, and the grading history. The reviewer marks the answer as pass (the question's full points, 1 point today) or fail (0 points) and can add a comment for the learner. Pass/fail is the only grading method for now; the grade request names its method and each grade stores it, so others can be added later and past grades keep their verdict even if the question's points change. "Next answer" moves straight to the next pending answer. When the last pending answer of an attempt is graded, Mentingo calculates the score and pass/fail result, records the quiz on the learner's progress, completes the lesson if the quiz is passed, and emits the quiz-completed and quiz-attempt-graded events, all in one transaction. Lesson, chapter and course completion are credited to the learner, not the reviewer. The learner then sees the final score, the points for each reviewer-graded question, and the reviewer's comment; when quiz feedback is disabled for the course, the points per question and the comment stay hidden. Re-grading an answer adds a new revision and keeps the history; it recalculates the attempt score and, when it is the learner's latest attempt, their quiz score on the lesson; it can complete a lesson that now passes, but never reopens a lesson that was already completed. When a re-grade turns a passed attempt into a failed one, the attempt is marked failed and the lesson keeps the new, lower quiz score, but the lesson stays completed and still counts the quiz as passed. Re-grading an older attempt after the learner has made a newer one changes only that older attempt, not the lesson progress. Answers from a run the learner has since repeated drop out of the queue and cannot be graded. The same goes for answers from a course switched back to draft; the reviewer gets a clear message instead, and the answers come back once the course is published. Answers from learners without an enrollment, such as freemium learners, can still be graded; their attempt gets its score and result, while lesson progress follows the same tracking rules as automatic grading.

When a reviewer grades the last pending answer of an attempt, and again on every re-grade, the learner gets an in-app notification (in the notifications feed, linking to the quiz lesson) and an email from the built-in "Quiz graded" automation with the course and lesson name, the score, and a button to the lesson. Reviewers are not notified per answer. Once a day (08:00 server time) Mentingo checks each organization's grading queue; when answers still waiting for review were submitted in the last 24 hours, every user who can grade answers (reviewers and admins) gets one email from the built-in "Grading queue digest" automation with the number of new answers, the total number waiting, and a link to the queue. Days without new answers send nothing. Both automations, their email templates and the in-app notification are available in every supported language, and admins can disable or adapt them like the other built-in automations.

When a quiz has a time limit, the learner starts the attempt explicitly. Mentingo records the start time on the server and sets the deadline as start time plus the limit; the learner's device only displays the countdown. Reloading the page or opening the quiz again returns the same open attempt with its deadline and the last autosaved answers, so the clock keeps running while the learner is away. Answers are autosaved while the attempt is open; saves arriving after the deadline are rejected, so only answers saved before the deadline survive. A submit sent up to 30 seconds after the deadline (to absorb network latency) is graded with the answers it contains. After that grace period, Mentingo ignores the sent answers and grades the attempt with the last autosaved answers. If the learner never submits, the attempt is finalized automatically after the deadline and grace period, either by a background job or, if that is delayed, the next time the learner opens or starts the quiz. Unanswered questions score 0 points, and so do autosaved answers to questions or options an author removed after they were saved. If the learner lost access to the course in the meantime, the abandoned attempt is cancelled instead of graded. A finalized timed attempt is scored, counts toward the attempt limit, completes the lesson only when it passes, and is followed by the normal retake rules. Untimed quizzes keep the original single-request submit flow. Open, unfinished attempts are excluded from feedback, statistics, and reports.

Time limits are not enforced in SCORM exports: the exported package contains the quiz questions but no timer, because the external LMS that runs the package controls the session.

When a learner retakes a quiz, Mentingo first checks the attempt limit and cooldown. If retake is allowed, previous answers are cleared and a new attempt begins. If not, the retake button remains disabled and the interface explains the remaining limit or cooldown.

## Key Technical Context

- Learner quiz delivery lives in `apps/web/app/modules/Courses/Lesson/Quiz.tsx` and the question components under `apps/web/app/modules/Courses/Lesson/Question`.
- Quiz authoring lives in `apps/web/app/modules/Admin/EditCourse/CourseLessons/NewLesson/QuizLessonForm`.
- The translated quiz editor loads the selected and base-language course variants through the existing localized course query. Questions are paired by their shared identity, while language-specific answer rows are paired by structural position.
- Quiz evaluation and retake orchestration are implemented in `apps/api/src/lesson/services/lesson.service.ts`; target-schema delivery and scoring live in `apps/api/src/quiz/services/quiz-runtime.service.ts`. Dedicated services coordinate quiz authoring and attempt persistence; repositories execute all database reads, writes, and transactions. Attempt writes participate in the caller’s transaction when one is supplied.
- Gap-filling result feedback is built from the localized target assessment definition and the learner's latest target attempt, including the submitted text and accepted answers.
- Passing quiz completion publishes a `QuizCompletedEvent` through the outbox and updates student lesson progress. A submission awaiting review publishes no events at all (no quiz-completed, lesson-completed, chapter or course events, so no gamification; reviewers learn about it from the daily grading digest); grading by a reviewer completes it.
- Questions authored in the quiz editor are worth one point each, and scoring uses each question's maximum points. Matching questions in partial mode award the share of correct pairs (for example 2 of 3 pairs = 0.67 point); all other questions, including all-or-nothing matching, award the full point or nothing. A question counts as correctly answered only when it earns its full points, so a partially correct matching question counts as wrong in the per-question summary, the submission result and learner statistics.
- Learners see the matches in an answer bank, in a stable shuffled order, and drag each match onto a prompt, the same way as in drag-and-drop fill-in-the-blanks: dropping on a filled item swaps the matches, dragging a match back to the bank removes it, and keyboard users pick up and drop matches with Space and move them with the arrow keys. The API accepts only matches that belong to the question and one answer per pair. Learners must place every match they are given. When some pairs are not translated into the learner's content language yet, those pairs stay empty and do not block submitting; when none are, learners see that no matches are available and the question scores zero.
- Matching pairs are copied with courses, exported and imported in course archives, translated by AI course translation, indexed by search, and exported to SCORM. The AI course-authoring assistant (Luma) cannot create matching questions yet and does not see existing ones; it refuses to update a quiz that contains them, so they are never removed by an AI edit.
- Open questions use grading mode `participation` (always correct) by default and `manual` when the editor sends `requiresReview: true`; migration `0235_keep_open_questions_participation_graded` moved existing open questions from `manual` to `participation`. Questions with grading mode `manual` make the attempt pending; "awaiting review" is derived from a pending attempt in the learner's active learning state (`apps/api/src/quiz/quiz-awaiting-review.sql.ts`), not stored on lesson progress.
- Reviewer grading lives in `apps/api/src/quiz-grading` (`/api/quiz-grading/answers`, `/filters`, `/answers/:id`, `/answers/:id/grade`), protected by `quiz_grading.read` and `quiz_grading.grade`. Each grade is a revision in `assessment_attempt_question_answer_reviews`. Finalizing reuses the same progress, lesson-completion and `QuizCompletedEvent` path as automatic grading (`StudentLessonProgressService.finishQuizProgress`), runs in the attempt's learning state, and also publishes `QuizAttemptGradedEvent` (also on re-grades). Its outbox handler (`quiz-grading/handlers/quiz-attempt-graded-notification.handler.ts`) creates a targeted system announcement (source type `quiz_grading`) and a `quiz_attempt_graded` notification event for the email automation. The reviewer digest is a daily cron (`QuizGradingCron`) that publishes a `quiz_grading_digest` notification event per tenant with a per-day (UTC date) occurrence id, so a re-run on the same day sends nothing new; the 24-hour window is fixed, not tied to the last sent digest. The digest counts the tenant's whole pending queue, including answers a reviewer (but not an admin) cannot grade because they are their own.
- SCORM exports grade in the learner's browser without a reviewer, so open answers there count as participation: any non-empty answer earns full points.
- Timed attempts are stored as in-progress assessment attempts with an expiry time and an autosaved draft. Starting, autosaving, and submitting use `POST /api/lesson/quiz-attempt/start`, `PUT /api/lesson/quiz-attempt/draft`, and the existing `POST /api/lesson/evaluation-quiz`. The lesson view returns `timeLimitMinutes` and the open `quizAttempt`. Abandoned attempts are finalized by a tenant-aware BullMQ delayed job (`quiz-attempt-expiration`) and lazily on the next start or lesson view. Finalization updates the attempt only while it is still in progress, so it cannot run twice; a start that finds an expired attempt finalizes it and answers with status `finalized` instead of an error, so the grading is not rolled back. Database CHECK constraints require a submission time for submitted attempts and an expiry for in-progress ones. The 30-second grace period is `ASSESSMENT_TIMED_ATTEMPT_SUBMIT_GRACE_SECONDS` in `@repo/shared`.
- Author feedback is stored per assessment as `feedbackMode` (`full` / `score_only` / `none`, `ASSESSMENT_FEEDBACK_MODES` in `@repo/shared`) and an ordered list of `{ id, minPercent, maxPercent, message }` ranges with a translatable message (`assessment_feedback_ranges`). Saves match ranges to stored rows by `id` (unknown or missing ids create new ranges, missing stored ids are deleted, display order follows ascending `minPercent`); a save in a non-base language must send the stored ids and bounds unchanged and only writes that language's messages. The server validates the 0–100 partition (`apps/api/src/quiz/validators/quiz-feedback-range.validator.ts`), picks and fills in the message at delivery (`apps/api/src/quiz/utils/quiz-feedback-message.ts`, returned as `quizDetails.feedbackMessage` only once the attempt is graded), and applies the course `quizFeedbackEnabled` setting as a master switch over the mode. Placeholders are not validated when the author saves; only `{{firstName}}` and `{{score}}` are filled in.
- The scale question type exists in code paths but is not exposed in the current question selector.

## Test Evidence

Frontend E2E coverage verifies quiz authoring for choice, text, fill-in-the-blanks, photo, and partially scored matching questions; confirms unavailable question types in the builder; verifies learner submission with every rendered question type, both with open answers counted as correct and with reviewer-graded open answers ending in "Waiting for review"; covers quiz retake, final-quiz retake after certificate completion, blocked progression after failing a required quiz, visible text gap-fill correction when feedback is enabled, and hidden gap-fill correction after retake when feedback is disabled. Unit coverage verifies base-language placeholder matching, including duplicate option display orders and readable gap-fill previews, as well as fallback correct-sentence rendering for completed fill-in-the-blanks questions. Backend E2E coverage verifies matching authoring, pair reordering, partial and all-or-nothing scoring, per-pair feedback, minimum pair validation, and rejection of foreign or duplicate pair answers. It also verifies feedback redaction for learners, admins, and course authors when the course setting disables feedback. It also covers translated authoring and feedback, base-language fallback, preserving answer identities after translated edits, and rolling back a submitted attempt with its caller’s transaction. Open-answer review coverage verifies the pending attempt and answers, incomplete lesson progress, no quiz-completed event, statistics ignoring the pending attempt, the awaiting-review lesson and course status with a partial result (graded questions only), the partial result hidden when quiz feedback is disabled, blocked resubmission and retake, and unchanged immediate grading for quizzes without manual questions. Frontend unit coverage verifies the server-clock countdown, the last-minute warning, the one-time automatic submit when time runs out, the start step before questions, and restoring autosaved answers; a browser E2E spec (`quiz-time-limit.spec.ts`) covers setting the time limit in the quiz settings and resuming a started attempt after reload. Timed-quiz E2E coverage (`timed-quiz-attempt.e2e-spec.ts`) verifies start and resume, the open attempt in the lesson view, autosave before and after the deadline, a submit within the grace period, a late submit graded with the autosaved draft, partial in-time submissions, finalization of abandoned attempts (one-time only, counted as an attempt, retake numbering), lazy finalization when the lesson is opened or started, a concurrent worker and lesson-view finalization, stale drafts after a question was deleted, cancellation after lost access, blocked retakes under attempt limit plus cooldown, exclusion of open attempts from statistics and feedback, and unchanged untimed submits. The master-course transfer E2E test verifies the time limit is copied and resynchronized. Grading coverage (`quiz-grading.controller.e2e-spec.ts`) verifies the queue, filters and grading view, finalizing the attempt with lesson completion, both events and the learner's points and comments, re-grade history without reopening the lesson, a re-grade that turns a fail into a pass, mixed automatic and reviewer-graded quizzes, refusing automatically graded answers and a reviewer's own answers, letting admins see and grade their own answers, a repeated course run, draft courses, grading an unenrolled freemium learner, completion credited to the learner, reviewer feedback hidden when quiz feedback is disabled, fractional points with the stored grading method, two last answers graded at the same time finalizing the attempt once, rejecting grades without a supported method, permission checks, and tenant isolation; a Playwright test verifies that grading the last answer completes the learner's lesson. Notification coverage (`quiz-grading-notifications.e2e-spec.ts`) verifies that nothing is sent while answers are still pending, that only the learner gets the in-app notification with the lesson link and the graded email, a new notification and email with the new score on re-grade, and a single reviewer digest per day that is skipped when no answers are new. The curriculum language E2E test proves that translated content remains editable while base-language structure is protected, but a browser-level assertion for the new placeholder presentation remains to be added. Author feedback coverage: unit tests verify the score-range partition rules, picking the range by the rounded-down score, filling in `{{firstName}}` and `{{score}}`, and holding the message until grading; lesson API E2E tests verify the three feedback modes and a message withheld while an open answer awaits review; `quiz-feedback-ranges.e2e-spec.ts` verifies the mode and ranges survive course duplication and that AI course translation translates every range message without changing the bounds; `course-transfer-quiz-feedback.e2e-spec.ts` verifies they are shared with another organization and replaced on a later sync; web unit tests cover the authoring validation, adding a range by splitting the last one, editable messages in a translation, and rendering the message on the result screen. Lesson API E2E tests also verify that translated messages stay on their range when the base language inserts or reorders ranges and that a translated save with changed bounds is rejected; the SCORM export test verifies the feedback mode lands in `course.json`. Known gap: SCORM packages do not show the range messages. Unit coverage also verifies the blank-selection reducer (`moveWordToBlank`) for moving, swapping and clearing words, that fill-in-the-blanks renders each blank as a numbered combobox and matching renders each pair as a combobox named after the pair, both with the click-to-choose instruction, and that a placed word stays draggable while a click still opens its list. The learner E2E flow fills the drag-and-drop gap and most matching pairs by choosing from the list and drags the first matching pair; keyboard-only and screen-reader (NVDA) completion of the final quiz is verified manually.
