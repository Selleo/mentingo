# AI Mentor Lessons Business Spec

## Business Overview

AI Mentor Lessons let course creators add interactive practice to a course. Instead of only reading content or answering a fixed quiz, learners can work with an AI Teacher or practice with a Roleplay character, then ask Mentingo to check whether the interaction satisfies the lesson goal.

For HR and L&D teams, this supports practice-heavy learning: handling a difficult customer, rehearsing feedback conversations, explaining a decision, reflecting on a policy scenario, or building confidence before a real workplace interaction.

The main workflow starts in the curriculum builder. A creator chooses Teacher or Roleplay, completes the focused fields for that experience, configures a structured AI Judge assessment, and adds any supporting resources. Teacher configuration defines the learning goal, subject expertise, content scope, teaching style, and optional feedback guidance. Roleplay configuration defines the scenario, the AI character's role, the learner's role, the AI character's goal, difficulty, and optional facts or constraints. Opening and additional instructions are shared across both types. The assessment can be intentionally lightweight, with a task goal but no scored criteria or blockers. When a course is available in multiple languages, creators can translate AI Mentor configuration and Judge text while keeping behavioral choices, scores, and rubric structure consistent across the course. A learner later opens the lesson, reads the task, chats with the AI Mentor, checks their result, and can retake the lesson if they need more practice.

AI-assisted authoring prepares reviewable Mentor behavior and completion-condition drafts from a creator brief or improves the configuration currently open in the editor. Mentingo checks structural and semantic quality before returning each draft, but does not save or publish it automatically.

## Who Uses It

- Course creators design AI-guided teaching activities or real-life roleplay scenarios.
- Multilingual content creators adapt the AI mentor scenario and structured assessment text to each course language instead of reusing one prompt for every audience.
- Learners practice a skill through conversation, receive AI responses, and submit the interaction for completion checking.
- HR and L&D administrators use AI mentor lessons to turn soft-skill or scenario training into measurable course progress.
- Course managers and administrators review AI mentor results in course statistics after learner progress exists.

## Feature Functions

- Create interactive AI mentor lessons from the curriculum builder.
- Configure the learner task, mentor name, avatar, Teacher or Roleplay experience, focused behavior fields, required Judge task goal, optional scored criteria and blocking errors, and supporting files.
- Generate Teacher or Roleplay behavior from a focused creator brief without letting AI choose or change the selected experience type.
- Improve or quality-check the complete unsaved Mentor configuration currently open in the editor.
- Generate or improve a structured Judge draft from the current lesson context while keeping the creator in control of review and save.
- Check the quality of generated, manually edited, or unsaved Judge values without changing them.
- Localize AI Mentor configuration and Judge text per course language while keeping behavioral choices, scores, thresholds, IDs, and assessment structure consistent across languages.
- Show missing Mentor and Judge translations as empty authoring fields and include them in the course's missing-translation warning and AI translation action.
- Offer a Teacher experience for guided learning and a Roleplay experience for realistic practice.
- Let the AI mentor address the learner by their real first name naturally in text and voice conversations without weakening the configured role.
- Let learners read the task, continue an existing conversation, send messages, and receive streamed mentor replies.
- Let learners ask Mentingo to check whether the conversation meets the lesson criteria.
- Mark the lesson complete when the check passes and show a retake path afterward.
- Show AI mentor result rows and read-only conversation previews in course statistics.
- Support microphone entry and voice mentor actions when the relevant voice configuration is available.

## End-User Value

AI Mentor Lessons make training more active and closer to workplace practice. Learners can rehearse decisions, conversations, and explanations in a safe course environment before applying them with colleagues, customers, or managers.

For HR and L&D teams, the feature makes practice trackable. Completion can be tied to the learner's interaction, and managers can review results without leaving the course reporting experience.

## How It Works

A creator adds an AI Mentor lesson, chooses Teacher or Roleplay, and completes one focused configuration dialog. Teacher asks for expertise, a task goal, content scope, teaching style, and optional feedback guidance. Roleplay asks for both participant roles, a scenario, character goal, difficulty, and optional facts or constraints. Task goals, content scope, scenarios, character goals, and optional behavior instructions support rich-text structure where longer guidance benefits from emphasis or lists. Both types can include an opening instruction and additional instructions. Changing between populated modes requires confirmation and permanently clears the prior mode's fields so hidden Teacher or Roleplay values cannot return later. The creator also configures at least the AI Judge task goal; criteria and blocking errors remain optional. The passing threshold accepts any whole percentage from 0 through 100; at 0%, every scored response meets the points requirement unless a blocking error causes failure. For a new lesson, applying the Mentor and Judge dialogs stages their configurations until the creator saves the lesson. For an existing lesson, each dialog saves its own configuration directly without saving unrelated lesson-form changes. In translated course languages, the dialogs expose exact translated text instead of masking gaps with base-language values. Saving translations immediately refreshes the course's missing-translation status so resolved warnings disappear without a page reload. Structural controls remain visible but disabled with an explanation because type, teaching style, difficulty, scores, thresholds, and assessment structure are shared across every language.

In the course base language, a creator can describe the assessment they need or ask AI to improve the complete draft currently in the form. The focused brief uses the same rich-text authoring surface as AI Mentor instructions, explicitly lists the task goal, scored criteria, passing threshold, and relevant blocking errors that AI will generate, and offers optional improvement shortcuts without submitting them automatically. Mentingo creates a structured replacement in the background, checks scoring completeness first, then checks whether the goal, criteria, guidance, examples, threshold, and blockers are meaningful. Generated task goals favor short bold labels and bullet points when several learner behaviors must be assessed, and no other rich-text formatting is generated; the compact creation summary flattens that formatting into readable plain text. Expected behaviors and every scoring-guideline description use a clear learner subject expressed entirely in the selected language, while creator-facing validation feedback uses translated product labels instead of schema keys. Deterministic structure findings are translated into the creator's interface language and use human-readable guidance instead of internal reference terminology. Semantic quality checking is a release gate rather than an editorial review: a usable rubric that supports consistent scoring and meaningful criterion titles passes without findings, while material contradictions, scoring ambiguity, unattainable thresholds, false blocking failures, failure to assess an explicit outcome, or unmistakable placeholder titles require revision. Examples calibrate one score level and do not need to demonstrate every stage of a named method unless that exact score requires it. A failed quality check pauses and clearly states that it is waiting for a decision. Up to three targeted findings are grouped under human-readable criterion or blocking-condition headings, including when deterministic checks find more structural problems internally. Compact orchestration references such as `C3` and `B2` stay internal and are replaced with the affected title or description before feedback reaches the creator. Quality feedback is the primary section, and already-applied AI changes are optional detail grouped under the same human headings. Text changes use complete inline word diffs instead of parallel before/after cards. Draft history is available only while improving an existing configuration and is hidden from the simpler initial-creation flow. The fixed footer presents **Continue** as the primary action and **Revise** as the secondary action. Revision submission is locked while the next draft is being requested, and repeated requests resolve to the same background job. Each numbered draft represents one complete AI proposal and its quality check. At most three Generator drafts are allowed. The creator can request cancellation and recover the latest short-lived progress after reconnecting without temporarily losing the current draft number or its history. Continuing with a draft advances to the Ready review without changing the lesson form. Ready removes redundant quality-success messaging and exposes one **Review assessment** action, which stages the generated configuration and opens the normal structured editor; the creator then uses the existing save action after reviewing or changing it. For an existing lesson, saving that edited assessment also synchronizes the staged lesson-form value so a later lesson save cannot restore the earlier generated version. Nothing is published automatically or saved without that normal editor action. The original creator instruction remains part of every quality check and revision so later repairs cannot silently undo the requested improvement. A successful or review-required result preserves existing rubric identities where the same item remains, including when criteria or blocking errors are reordered or removed between AI drafts. Generated passing thresholds are normalized to round ten-point increments, usually 60%, 70%, or 80%, so the result is understandable rather than an incidental percentage such as 67%. An independent quality check follows the same access and language rules but never generates or persists changes, and its findings can start an improvement immediately without another text brief. It returns at most three concise, high-confidence findings. On later drafts, the Validator performs a closure check against the immediately preceding findings and the fields changed by the repair; it does not reopen untouched neighboring score examples or reveal unrelated concerns one attempt at a time. A clean pass has no findings; a pass with optional suggestions is labeled separately and still permits AI improvement. The creator can cancel an in-progress independent check from its loading dialog. Criterion guidance, examples, expected-behavior text, and blocking-error descriptions grow with their content up to a bounded number of lines, then scroll internally without exposing a manual resize handle.

AI-assisted creation remains the primary empty-assessment action on the user-facing **Completion conditions** card, with manual configuration as the quiet alternative. Creators configure **AI Mentor behavior** first so assessment generation can use the intended Teacher or Roleplay context; until then, **Create with AI** remains visible but disabled with an explanatory tooltip. Once configured, the card exposes only **Review assessment**; improvement and quality checking live inside the structured editor under a compact AI assistance command menu. Creators enter one focused rich-text brief for creation or an independently requested improvement, while quality-check findings can start improvement directly. That transition closes the standalone quality result so the generation flow is the only active dialog. The task goal accepts only bold text and bullet lists, keeping the assessment context structured without allowing presentation-heavy lesson content. If a provider or structured-generation request fails, the creator sees a stable recovery message while technical diagnostics remain in server observability rather than appearing in the course UI.

AI Mentor behavior authoring keeps the lesson form compact. The main form contains the learner-facing task and identity settings, while four lightweight scenario examples can populate the task, Mentor behavior, and completion conditions together. Each example is a one-time starting action rather than a persistent selection; examples also provide practical fine-tuning values such as scenario constraints, opening behavior, or feedback guidance. If authored content already exists, Mentingo asks for confirmation before replacing it. A single **AI Mentor behavior** card lets the creator configure behavior manually or start with AI.

For AI creation, the creator first selects Teacher or Roleplay and then describes the scenario or learning experience needed for that role. The selected type is trusted product context: AI generates only the fields belonging to that type and cannot return, recommend, or change the type. In Roleplay, the generated fields keep the AI character and learner roles separate; the character goal is explicitly the AI character's objective, while opening and additional instructions describe only the AI character's behavior. Quality feedback uses the active authoring language and presents localized field names. For improvement, Mentingo sends the complete current unsaved configuration and its existing type, so the proposal reflects edits that have not been saved yet. If the creator manually changes type, later improvement applies to the new type and its fields. An independent quality check evaluates the same current unsaved configuration without changing it. Generation runs in the background, can be cancelled or recovered after reconnecting, and may offer a limited revision when quality findings remain. Reviewing a result stages the type-matched proposal in the normal Mentor editor; the creator still decides whether to save it. Results created for an earlier type are rejected after a type switch.

The Mentor editor keeps **Improve with AI** and **Check quality with AI** together in the bottom **AI assistance** menu, alongside the normal save and cancel actions. This keeps the card focused on the current configuration while making both actions operate on the exact unsaved draft. Generation follows the same visible review sequence as Completion conditions: a stage tracker shows draft creation, quality check, and readiness; quality findings offer **Revise** or **Continue**; and the final review exposes one **Review configuration** action that returns the draft to the normal editor before saving.

When a learner opens the lesson, Mentingo initializes or reuses that learner's conversation thread in the learner's active language. The learner sees the task, sends messages through a composer that grows to a bounded height before scrolling, and receives AI mentor responses guided by the matching localized scenario. When they choose the check action, a separate assessment status replaces the conversation controls while Mentingo evaluates every configured criterion, detects configured blocking errors, and calculates points, percentage, and pass/fail on the server. The Judge does not append an artificial Mentor message or generate a separate overall summary: the result presents the deterministic outcome plus feedback attached to each criterion or triggered blocking error. If neither exists, the result explains why detailed feedback is unavailable. A passed check completes the lesson; a retake archives the prior thread and starts fresh progress.

AI Mentor conversations should sound like direct human dialogue rather than generated forms or recaps. Roleplay characters treat lesson instructions as private acting direction, keep the character and learner roles stable across every turn, attribute offers and constraints to the participant who actually stated them, react to the learner one conversational move at a time, and avoid parroting the learner's full brief. They return only the character's spoken dialogue in plain text, expressing attitude through wording instead of stage directions, scene narration, Markdown emphasis, or assistant-style formatting. Teacher conversations likewise keep response length proportional, avoid mandatory end-of-turn questions, and default to natural prose. Platform-owned prompt rules define how each teaching style and Roleplay difficulty behaves so identical configuration does not depend on ad hoc interpretation.

AI Mentor chat displays ordinary currency amounts as conversational text rather than interpreting pairs of dollar signs as a math formula. Explicit double-dollar math remains available for lessons that intentionally need mathematical notation.

Mentingo gives the AI mentor the current learner's first name so it can address them occasionally when that makes the exchange warmer or clearer. The mentor uses language-aware name forms only when confident, avoids inventing gendered titles or honorifics, and keeps the learner's identity separate from its own persona. The same rule is part of the shared system prompt, so it applies to the opening welcome, normal text responses, and voice conversations while Roleplay characters remain in character.

Learners can also create one standalone AI Mentor practice per UTC day from the personal dashboard. They describe the conversation they want to rehearse in one free-form scenario field, or choose one of three concise examples for a delayed order, an order-entry mistake, or a customer-data request. The suggestion popover shows only those short labels; selecting one fills the full scenario into the composer for review before submission. Mentingo stores that learner scenario with one session for the tenant/user/UTC date, generates a structured Roleplay AI Mentor configuration, and then generates the Judge configuration with that Mentor configuration as context. The practice brief is treated as the learner's learning goal: if the learner wants to learn how to handle a difficult client, the difficult client becomes the AI counterpart and the learner becomes the professional handling the conversation. The practice title comes from the learner's scenario, while the generated counterpart role includes a plausible human name and becomes the Mentor's display name. Practice behavior is generated by the same structured AI Mentor configuration pipeline used by course authoring; there is no separate free-form practice-instructions or metadata-generation prompt. The conversation prompt explicitly requires fluent, idiomatic output in the selected language, including natural Polish grammar and register. After creation, the dashboard refreshes the daily practice while background generation progresses so the first Mentor message appears as soon as the generated thread is ready. The learner sees the same session for the rest of that UTC day and can continue its conversation from the dashboard.

Standalone practice reuses the AI Mentor conversation experience but is deliberately separate from course learning. It does not update course or lesson progress and does not create a calendar event. Its generated Judge configuration evaluates the completed rehearsal and provides feedback, while failed generation can be retried without creating another daily session.

Voice behavior has two layers. Learners can use microphone-assisted entry in the lesson UI, and when Luma voice mentor configuration is enabled, the primary message action can switch into a voice mentor mode. Luma is Mentingo's connected AI service for voice-enabled mentor behavior; the authoring form also exposes voice configuration controls when that service reports voice support.

## Key Technical Context

- Learner UI lives in `apps/web/app/modules/Courses/Lesson/AiMentorLesson`.
- Authoring UI lives in `apps/web/app/modules/Admin/EditCourse/CourseLessons/NewLesson/AiMentorLessonForm`.
- AI thread, chat, judge, and retake endpoints live in `apps/api/src/ai/ai.controller.ts`.
- AI-assisted Judge generation and quality-check endpoints live under `/ai/judge-configuration`; lesson-domain authorization derives the course base language and verifies lesson ownership.
- AI-assisted Mentor generation and quality-check endpoints live under `/ai/mentor-configuration`. They use the same lesson-domain authorization boundary, short-lived background-job ownership, and reconnectable snapshot pattern as Judge generation.
- Mentor generation currently uses Mentingo's Core structured-output model path because the installed Luma integration does not expose dedicated Mentor configuration generation or validation capabilities. The model output omits the Teacher-or-Roleplay discriminator; the API reattaches the creator-owned type after validating the generated fields.
- Judge generation runs as short-lived background jobs. Progress is delivered only to the authenticated creator's socket room, while ownership-checked snapshot and revise endpoints support reconnect recovery and creator-approved attempts. Referenced drafts remain private job metadata between attempts, and deterministic revision job IDs prevent duplicate background work; generation attempts are not stored as permanent course data.
- Generator and Validator model calls use dedicated strict structured-output schemas. Optional model values are represented as nullable at that boundary, and provider/schema diagnostics are never exposed in creator-facing generation progress.
- Judge configuration generation and quality validation follow the tenant's configured AI Mentor Judge provider. When Luma is selected, Mentingo uses Luma's dedicated generator and validator model profiles; unavailable or invalid Luma responses fall back to the Core model while preserving the same strict output contract.
- Standalone practice uses `GET /api/ai/practice/today`, `POST /api/ai/practice`, `GET /api/ai/practice/:id`, and `POST /api/ai/practice/:id/retry`; its protected page is `/ai-mentor/practice/:id`.
- AI mentor lesson create/update endpoints live in `apps/api/src/lesson/lesson.controller.ts`.
- Learner AI access requires `AI_USE`; authoring requires `COURSE_UPDATE` or `COURSE_UPDATE_OWN`.
- AI Mentor configuration text and Judge text use exact-language values in the admin editor so missing translations remain visible. Learner delivery may still use the course base language as a fallback where a translation is absent.
- The API determines whether a localized Judge configuration is incomplete and returns that status with the configuration, so the authoring warning uses the same backend translation rules as course-level translation generation.
- The structured AI Judge rubric is the learner Judge's source of truth. Each criterion has a maximum score from 1 through 5. The model returns short references such as `C1` and `B1`; server code maps them to trusted rubric records, validates awarded scores, and calculates totals, percentage, and pass/fail deterministically.
- Luma and the local AI runtime return the same criterion and blocking-error evidence shape. Provider output never decides the final score directly; the Mentingo API applies the trusted rubric and deterministic calculation after either provider responds.
- Existing localized completion-condition values are preserved as Judge task goals during migration. The legacy source column is then removed, and the learner Judge uses only the structured Judge configuration.
- The course's missing-translation generation includes the localized fields for the selected AI Mentor type plus Judge task goals, criterion titles and expected behaviors, scoring guidance and existing examples, and blocking-error descriptions without changing Mentor behavior, assessment structure, or scoring.
- Judge criteria are optional. When a configured assessment has no criteria, its total maximum score is zero and the scored assessment is satisfied without applying the percentage threshold; the learner passes unless a blocking error is triggered.
- AI Mentor configuration supports exactly one active subtype: Teacher or Roleplay. The root configuration stores shared opening and additional instructions, while the selected subtype stores only its focused fields. Changing type replaces the previous subtype transactionally.
- New AI Mentor lessons require a Judge configuration at creation. During the current Luma compatibility phase, generated courses still provide the legacy AI Mentor instruction/type payload and Mentingo converts it into a structured configuration with safe defaults during import. A later Luma contract update will provide the complete Teacher-or-Roleplay schema directly and remove this adapter.
- At evaluation time, the API loads the localized task goal, criteria, exact score guidance, accepted examples, and blocking errors as one rubric query. The learner transcript is wrapped in an explicit untrusted-submission boundary and passed to the single authoritative generated Judge prompt.
- Completed judgements retain immutable criterion titles, blocking-error descriptions, awarded/max scores, statuses, and learner-safe evidence. Creators may later remove rubric criteria or blocking errors without deleting or changing the learner's historical result.
- Master-course export and synchronization copy the complete localized Judge graph. Synchronization preserves the target configuration identity while replacing its current criteria, score guidance, examples, and blocking errors transactionally.
- AI Mentor types, Teacher teaching styles, Roleplay difficulties, and voice mode constants live in `packages/shared/src/constants/aiMentorTypes.ts` and `packages/shared/src/constants/aiMentorVoice.ts`.
- Learner-name personalization is resolved from the authenticated conversation thread rather than caller-supplied chat content. The name is marked as untrusted prompt data, and the shared policy explicitly preserves the configured Teacher or Roleplay persona.
- `ai_mentor_practice_sessions` stores the UTC practice date, language, learner scenario, title, AI Mentor name, generation status, and error code. A tenant/user/date unique index makes concurrent creation idempotent. Its generated behavior is stored in the shared structured AI Mentor configuration tables as a Roleplay configuration linked directly to the practice session.
- Every AI Mentor thread has exactly one source: a course AI Mentor lesson or a standalone practice session. Practice ownership is checked against the current user before session, thread, or message access.
- Practice creation publishes a durable outbox event. A dedicated BullMQ worker creates the structured Roleplay configuration through the shared AI Mentor configuration generator, derives the Judge from that configuration, creates the thread and welcome message, and marks the session ready or failed.

## Test Evidence

Frontend E2E tests cover creating and previewing an AI mentor lesson, uploading an AI mentor resource, learner entry into the interaction, voice action visibility when Luma voice is enabled or disabled, the full chat/check/retake flow, and AI mentor statistics review. Focused component tests additionally verify the structured Mentor and Judge editors, translation-mode locking, generation-state mapping, creator-owned Mentor type guards, review controls, and independent validation disclosure.

The full AI chat E2E test is environment-dependent and skips when OpenAI is not configured. Backend E2E tests cover thread ownership, authentication, authorization, message retrieval, localized AI mentor prompt selection, learner-name resolution from thread ownership, required Mentor and Judge configuration at lesson creation, configuration permissions, translation-only updates, and cross-tenant master-course graph copy/resynchronization. Focused backend tests verify the Teacher/Roleplay configuration union, subtype graph integrity, exact-language reads, backend-owned translation completeness, stable style/difficulty prompt behavior, shared learner-name prompt composition, deterministic Judge scoring, blocking-error overrides, structured prompt safeguards, local-runtime fallback compatibility, Luma generator and validator routing with Core fallback, Mentor generation schemas and creator-owned type preservation, deterministic Mentor validation, generation workflow attempts, job ownership and cancellation, provider-error sanitization, course and lesson authorization, and stable ID reconciliation. Focused frontend tests cover manual Mentor mode selection, required rich-text fields, type-switch confirmation and stale-field clearing, scenario-example drafts, compact card states, translation mapping, new-lesson staging, Mentor generation type guards, and the Judge generation and review flow. Curriculum E2E coverage creates a lesson through the structured Roleplay dialog, saves the structured Judge, reopens the configuration, and verifies translated configuration updates refresh course translation status. Realtime transport does not yet have full editor-level end-to-end coverage. Generated-course import validation is currently covered by schema and service-level validation rather than a dedicated end-to-end Luma import test.
Focused backend regression coverage also verifies subtype-only translation updates that omit unchanged shared Mentor instructions.

Standalone practice tests cover local-day calculation, concurrent daily uniqueness, session and thread ownership, successful worker setup, failed generation and retry, and deterministic test doubles that never call an external AI provider. Frontend coverage verifies the form, generation polling, ready conversation, failed retry, and dashboard continuation states.
