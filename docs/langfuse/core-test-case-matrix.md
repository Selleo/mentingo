# Core test and evaluation coverage matrix

The catalogue defines **103 Core cases** (67 prompt/embedding cases and 36 native application cases). Run outcomes belong in Langfuse or ignored local reports. This finite synthetic suite does not establish every product interaction or deployed behavior. Source: [feature-catalogue.v1.json](../../apps/api/test/evaluations/feature-catalogue.v1.json). See [strategy and ownership](README.md) and [runbook](core-evaluation-runbook.md).

Catalogue: **31 feature datasets / 103 entries / 98 distinct complete input objects**. The translation pair, daily-practice grounded/roleplay pair and four embedding entries share complete input objects. Different feature labels or execution layers do not make those independent input variations.

## Evidence legend

- **Existing normal test** records ordinary code-test coverage separately from the executed model/native cases.
- **Prepared** means offline descriptors were checked; preparation alone is not execution.
- **Pass** means a captured result matches the current published input/oracle contract and has a verified feature-judge score bound to the exact experiment root. Failed hard checks or missing evidence cannot count as a pass.
- **Fresh execution / saved-output reassessment** are distinguished in the report. Importing an earlier capture does not rerun the application. Original failed trials remain preserved.
- Native HTTP, socket, workflow, receipt/readback and independent audio-listening evidence establish only their respective observed boundaries. They do not imply production deployment or complete human calibration.

## Known limits

- Preparing the 103 descriptors is not executing the cases. Reports produced by the package commands contain execution results; dataset publication does not establish a pass.
- The stale-baseline native driver now verifies a real concurrent edit, typed conflict and canonical readback. Audio coverage is limited to its declared fixtures and independent listening receipts, rather than a comprehensive perceptual benchmark. Duplicate input groups need diversification; complete human/domain calibration remains outstanding.
- Existing product tests are inventoried separately from model/application experiments. Mocks do not establish provider behavior or live delivery.
- Online rules cannot evaluate uninstrumented calls. Core global-search embedding telemetry is intentionally disabled. Model-only prompt cases do not establish Core permissions or Luma production prompt behavior.
